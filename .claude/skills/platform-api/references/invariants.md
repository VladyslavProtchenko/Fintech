# API Invariants — Never Violate

These rules apply to EVERY generated backend regardless of customization.

## Shared Packages

All shared packages are workspace dependencies (`"workspace:*"` in package.json).

### @fintech/payment-sdk
- ALL payment operations go through this SDK
- Never call payment-service HTTP endpoints directly
- Import: `import { PaymentClient } from '@fintech/payment-sdk'`

### @fintech/shared-auth
- Provides: `createAuthModule()`, `JwtAuthGuard`, `CurrentUser`, `hashPassword`, `comparePassword`
- Add `createAuthModule()` to `app.module.ts` imports — provides JwtStrategy and JwtAuthGuard globally
- AuthModule must ALSO import `JwtModule.registerAsync(...)` directly — createAuthModule's @Global does NOT propagate JwtService to child modules
- Never duplicate auth utilities locally

### @fintech/shared-prisma
- Provides: `withPrismaAdapterPg(PrismaClient)` mixin
- PrismaService is one line: `export class PrismaService extends withPrismaAdapterPg(PrismaClient) {}`
- Never create manual Pool setup

### @fintech/shared-health
- Provides: `createHealthModule(Controller, { imports })` factory
- WARNING: This returns DynamicModule — CANNOT use with `extends`
- Use LOCAL HealthModule with TerminusModule instead:
  ```typescript
  @Module({ imports: [TerminusModule], controllers: [HealthController] })
  export class HealthModule {}
  ```

### @fintech/shared-config
- Provides: `BaseEnvironmentVariables`, `createValidator`
- Extend BaseEnvironmentVariables for platform-specific vars
- Do NOT redefine NODE_ENV, PORT, DATABASE_URL (already in base)
- Use `createValidator(EnvironmentVariables)` as ConfigModule validate function

## Prisma 7

- NO `url` in datasource block — Prisma 7 removed it
- `prisma.config.ts` at service root with `defineConfig({ datasource: { url: process.env['DATABASE_URL'] } })`
- Generated output MUST be inside `src/` (e.g., `output: "../src/generated/prisma"`)
- Import from `generated/prisma/client` (not `generated/prisma`)
- Import `'dotenv/config'` in prisma.config.ts

## TypeScript Config

```json
{
  "extends": "../../../tsconfig.base.json",
  "compilerOptions": {
    "rootDir": "./src",
    "incremental": false,
    "paths": {
      "@fintech/payment-sdk": ["../../../packages/payment-sdk/dist/index"],
      "@fintech/shared-auth": ["../../../packages/shared-auth/dist/index"],
      "@fintech/shared-prisma": ["../../../packages/shared-prisma/dist/index"],
      "@fintech/shared-health": ["../../../packages/shared-health/dist/index"],
      "@fintech/shared-config": ["../../../packages/shared-config/dist/index"]
    }
  }
}
```

CRITICAL: paths point to `dist/index` (3 levels up), NOT source files. Otherwise rootDir expands and build breaks.

## NestJS Config

- nest-cli.json: tsc builder (NOT SWC), `deleteOutDir: true`
- `incremental: false` in tsconfig — prevents tsbuildinfo caching issues with deleteOutDir

## Auth Flow

- Registration creates LOCAL User only — NO payment-service call
- User model: `paymentClientId? @unique` + `walletId? @unique` (both optional for lazy provisioning)
- `ensurePaymentClient(userId)` creates payment-service client on FIRST wallet access
- After ensurePaymentClient: MUST validate walletId is not null (throw BadRequestException if wallet not created by payment-service)

## Payment Bridge

- Map SDK `Transaction` → `MappedTransaction` (hide walletIds, derive direction, resolve counterparty names)
- Balance fetched via `getClient()` → `wallet.balance` (SDK has no `getBalance()`)
- Self-transfer check: `sender.id === recipient.id` → reject before calling SDK
- Idempotency keys: `crypto.randomUUID()` generated by backend
- Transfer recipient resolved from LOCAL User table by email

## Error Handling

- GlobalExceptionFilter catches THREE types:
  1. `HttpException` — return as-is in unique format
  2. `PaymentServiceError` (from SDK) — 422 for insufficient funds, 502 for other
  3. Unknown errors — `console.error()` first, then return generic 500
- Payment-service IDs and error structure NEVER leaked to frontend

## Endpoints

- `GET /health` — public, no auth guard
- Swagger setup path: `'docs'` (not `'api/docs'`) — Caddy strips `/api/` prefix
- Env validation at startup — app crashes on missing vars

## Dockerfile

Multi-stage build pattern:
- Builder: `corepack enable`, copy workspace root files + packages + platform api, `pnpm install`, prisma generate, build
- Production: `corepack enable`, copy workspace root files, copy full `/app/packages` from builder, copy dist + generated + prisma files, `pnpm install`, expose port, CMD with prisma migrate deploy
